四条线，覆盖一次作业评审的完整链路

结构决定可维护性，布局决定在手机上会不会塌，可访问性决定会不会被扣分，代码规范决定改动成本。四类各占一块分数，缺一块报告就不完整。

结构体检 30 分

DOCTYPE、html lang、语义标签（header/nav/main/footer）、标题层级不跳级、区块划分是否只有 div。

布局体检 25 分

viewport、断点数量、flex 还是 grid、盒模型是否统一、窄屏横向滚动、图片是否变形。

可访问性 25 分

图片 alt、正文对比度 4.5:1、键盘可聚焦、焦点轮廓可见、表单 label 关联。

代码规范 20 分

内联样式数量、class 语义化命名、缩进一致性、CSS 重复片段、失效资源链接。

五步工作流

先让机器判掉能判的，剩下需要人来判断的部分才交给人，这样报告不会又长又空。

  1. 跑体检脚本 check_page.py 扫一遍，拿到缺 DOCTYPE、缺 alt、重复 id、标签未闭合这类硬问题。
  2. 读布局骨架 判断主干用的是 flex、grid 还是浮动堆版，标出魔法数字和绝对定位。
  3. 对照清单 按 layout-checklist.md 四个维度逐条判"过 / 不过 / 待确认"，不写模糊结论。
  4. 给替换代码 布局问题必须附可直接替换的片段，模式取自 css-patterns.md，不拆碎改。
  5. 出分级报告 必修 → 建议 → 做得好的地方 → 下一步，问题一律按严重程度排序。

快速开始

Python 3.8+ 即可运行，脚本只用标准库，不需要 pip 安装任何东西。

# 体检单个页面
python scripts/check_page.py index.html

# 体检整个目录，并把报告写到文件
python scripts/check_page.py ./pages --md report.md

# 触发 Skill（把 SKILL.md 交给 AI 使用）
帮我体检一下这个页面，按必修/建议分级给清单

目录结构

SKILL.md 是说明书，references 是判定口径，scripts 是执行器，index.html 是发布到 GitHub Pages 的展示页。

web-design-skill/
├── SKILL.md                 # 触发条件 + 工作流程 + 输出模板
├── README.md                # 项目说明与使用方法
├── index.html               # GitHub Pages 落地页（就是你现在看的这页）
├── assets/style.css         # 可复用页面骨架样例
├── references/
│   ├── layout-checklist.md  # 四维度清单 + 扣分口径
│   └── css-patterns.md      # 栅格 / 居中 / 粘性页脚 / 卡片组
├── scripts/check_page.py    # 零依赖体检脚本
└── LICENSE
